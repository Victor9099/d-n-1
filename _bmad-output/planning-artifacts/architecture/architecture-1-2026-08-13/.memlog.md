- (decision) Product chứa dữ liệu chung; mỗi tổ hợp size và màu là một Variant/SKU có định danh, giá và tồn kho riêng. Binds catalog, cart, order, API và database; prevents product-level price/stock assumptions diverging across agents.
- (decision) Chọn monorepo modular monolith: storefront, dashboard, backend/API và shared contracts có ranh giới module/app rõ trong một repository; nghiệp vụ backend không tách microservices ở MVP. Binds repository topology and dependency direction; prevents premature distributed-service divergence while enabling parallel agents.
- (decision) Tách apps/storefront và apps/admin thành hai web app có build/deploy boundary riêng; chỉ chia sẻ design tokens, UI primitives và generated API client, không chia sẻ page hoặc business state. Binds UI topology; prevents admin and storefront release/runtime concerns from coupling.
- (decision) Chọn REST + OpenAPI schema-first; openapi.yaml là nguồn chân lý cho HTTP contracts, generated clients/types/mocks được các web apps tiêu thụ, backend triển khai contract và browsers không ghi database trực tiếp. Binds frontend/API integration and mutation path; prevents handwritten DTO drift and unauthorized direct persistence.
- (decision) Chọn modular vertical slices + ports/adapters: các module Catalog/Inventory, Cart, Orders, Payments, Content và Identity sở hữu use cases và persistence ports; HTTP, database, payment và media là adapters; cấm truy cập chéo repository/bảng giữa module. Binds backend dependency direction; prevents tightly coupled layered monolith and cross-module data ownership conflicts.
- (decision) Cart không giữ tồn; checkout tạo inventory reservation theo SKU với thời hạn. Payment webhooks phải idempotent; backend là authority duy nhất chuyển reservation thành sold stock hoặc giải phóng khi hết hạn/thất bại. Binds Inventory/Checkout/Orders/Payments; prevents overselling, duplicate fulfillment and client-authoritative payment state.
- (decision) Thị trường MVP là Việt Nam; VND là currency mặc định và monetary values được lưu dưới dạng integer VND, không dùng floating point. Binds pricing/orders/payments/API/database; prevents currency ambiguity and rounding divergence.
- (decision) MVP supports COD and VNPAY; MoMo is deferred behind the Payments port. Backend verifies VNPAY checksum/IPN and is the sole authority for payment state; browser return redirect is display-only. Binds Payments/Orders/security; prevents provider coupling and client-forged payment confirmation.
- (decision) MVP supports guest checkout plus optional customer accounts. Orders snapshot recipient/contact/address at placement; later account linking does not rewrite historical order data. Guest order lookup uses a high-entropy token stored hashed, never a sequential ID alone. Dashboard always requires authenticated, server-authorized staff. Binds Identity/Cart/Orders/privacy; prevents checkout friction, history mutation and order enumeration.
- (decision) MVP dashboard RBAC roles: Owner/Admin manages all resources, staff and configuration; Catalog Editor manages products/SKUs/media/posts without payment or user administration; Order Operator views and advances order/fulfillment states without catalog or role changes. Backend enforces every permission; UI visibility is not authorization. Binds Identity/Admin/API; prevents privilege drift and client-only access control.
- (decision) Product and Post share draft→published→archived lifecycle. Public storefront reads published only; draft preview requires authenticated admin and expiring authorization. Slugs are unique and published slug changes retain redirects. Records referenced by Orders are archived, never hard-deleted. Publish/unpublish emits a cache-revalidation event. Binds Catalog/Content/Storefront/SEO; prevents draft leakage, broken URLs, historical deletion and stale public content.
- (decision) Media binaries live in object storage behind a CDN; database stores MediaAsset metadata and object keys. Admin obtains server-authorized presigned upload, uploads directly, then backend validates/finalizes attachment; orphaned/expired objects are cleaned asynchronously. MediaStorage port isolates provider. Binds Admin/Catalog/Content/infrastructure; prevents API file bottlenecks, broken references and provider lock-in.
- (direction) Bổ sung delivery governance cho multiagent: Conventional Commits được enforce bằng commitlint + Husky, có hướng dẫn agent chọn type/scope và tạo commit nguyên tử; bổ sung Docker cho local development và DevOps/deployment.
- (decision) Operational scope currently targets local development only. Docker Compose is the canonical local topology for storefront, admin, API, worker, PostgreSQL and S3-compatible storage emulator with healthchecks. Production platform, rollout topology and provider selection are deferred until deployment is requested; production containers must not be implied by local Compose defaults. Binds developer environment; prevents agent-specific setups and premature cloud decisions.
