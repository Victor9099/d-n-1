- (decision) Confirmed inputs: clothing-commerce SPEC.md with four contract companions and final Architecture Spine; no brand assets, mockups or reference sites supplied yet.
- (decision) Use UI UX Pro Max as design-intelligence research inside BMad UX; its recommendations remain options until the user selects them, while DESIGN.md and EXPERIENCE.md remain the final UX contracts.
- (assumption) Working brand is ÊM: Vietnamese clothing that feels calm, comfortable, honest, and unpressured; replace when final brand assets arrive.
- (decision) Storefront direction: warm editorial minimalism, mobile-first, generous whitespace, large product imagery, dark-ink primary actions, restrained ochre accent, no fake urgency.
- (decision) Admin direction: calm data-dense workspace sharing brand tokens but using compact Inter typography, slate surfaces, semantic status colors, tables and filters optimized for desktop.
- (decision) Typography: Playfair Display for storefront editorial headings and Inter for body/UI; admin uses Inter throughout. Local fallbacks are Georgia and system sans.
- (decision) Motion is functional only: 150-220ms opacity, color, and transforms up to 4px; no GSAP dependency for MVP; reduced-motion removes nonessential transforms.
- (assumption) MVP UI language is Vietnamese, displayed dates use dd/MM/yyyy and Asia/Ho_Chi_Minh, while API timestamps remain UTC.
- (decision) Storefront IA: Mới về, Bộ sưu tập, Bài viết, Tìm kiếm, Tài khoản, Giỏ hàng; checkout and order tracking are dedicated pages, not modal-only flows.
- (decision) Admin IA is role-aware: Tổng quan, Sản phẩm, Bài viết, Đơn hàng, Thư viện, Nhân sự, Cấu hình; the server remains authorization authority.
- (decision) Accessibility floor is WCAG 2.2 AA: 4.5:1 body contrast, visible focus, keyboard-complete flows, 44x44px touch targets, 16px mobile body text, labels and error summaries, never color-only state.
- (decision) Key screens to render: storefront home/catalog desktop, product detail mobile, checkout payment-pending mobile, and admin orders desktop.
- (assumption) MVP is light-theme only; admin authoring is desktop-first and tablet-usable, while customer storefront is fully mobile-first.
- (decision) Reference research signals: large 4:5 product imagery, warm neutral palette, clear catalog hierarchy, compact admin status tables; references inform direction but do not override product or architecture spines.
- (decision) Promoted four confirmed key-screen mocks: storefront home/catalog, mobile SKU product detail, mobile VNPAY pending, and desktop admin delivery-failed orders. Coverage includes canonical entry, SKU decision, payment uncertainty, and operational exception.
- (assumption) Non-blocking UX assumptions retained for review: working brand ÊM, light-only MVP, Vietnamese locale, final-five-minute quote countdown, admin phone limited to simple urgent tasks, and slash-to-search admin shortcut.
- (event) UX draft spines and four offline key-screen mocks completed; awaiting optional Reviewer Gate before finalization.
- (override) User explicitly adds GSAP to MVP for smoother motion, overriding the earlier no-GSAP decision. GSAP is limited to storefront editorial reveals, product-grid entrance, checkout status crossfade, and admin detail-panel continuity; it never gates navigation, data, focus, or server state.
- (decision) GSAP motion contract: use gsap and @gsap/react; ScrollTrigger only on storefront below-fold sections; durations 180-400ms, transform/opacity only, 30-50ms stagger for at most 8 items, animations interruptible and scoped with useGSAP cleanup.
- (decision) Reduced motion is a hard alternate path: gsap.matchMedia honors prefers-reduced-motion, renders content visible without transforms, removes parallax/stagger, and uses at most a short opacity crossfade. No-JS and hydration-before-GSAP states remain fully usable and visible.
- (change) Reviewer Gate ran rubric, accessibility and commerce-edge lenses. Remediation added control-boundary tokens, inherited primitive registries, full surface-state coverage, secure commerce/session semantics, accessibility-correct mocks and GSAP progressive-enhancement guards.
- (event) Reviewer Gate consolidated: initial reports preserved; no Critical or High planning-contract finding remains open. Runtime OpenAPI generation and browser/assistive-technology evidence remain implementation gates.
